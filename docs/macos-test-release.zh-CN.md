# macOS 自用测试包

本 Fork 的测试包面向 macOS 14 及以上，包含 Apple Silicon 和 Intel 两种架构。
**这是 ad-hoc 签名、未经 Apple 公证的测试包，不是经过 Apple 验证的正式安装包。**
Windows 的构建、签名和发布流程保持原样，本流程不会发布 Windows 安装包。

## 下载与安装

1. 打开[本 Fork 的 Releases](https://github.com/xionghaizhi/WeChatBridge/releases)，选择标为 `Pre-release` 的 macOS 测试版本。
2. 下载该版本的 `.dmg`、`SHA256SUMS.txt` 和需要的场景 JSON。`build-info.txt` 记录实际源码提交。
3. 在下载目录执行 `shasum -a 256 <安装包文件名.dmg>`，与校验文件中相应行比较。校验值用于检查下载完整性，不等同于 Apple 公证或发布者身份认证。
4. 打开 DMG，将“微信流.app”拖入 Applications。先退出正在运行的微信流。
5. 首次启动可能被 macOS 拦截。仅在确认来源、版本和校验值后，按[Apple 的说明](https://support.apple.com/zh-cn/102445)在“系统设置 → 隐私与安全性”中处理；不要关闭整台电脑的安全检查。若系统明确报告恶意软件，不要绕过。

本 Fork 暂时沿用原应用的标识和 `~/Library/Application Support/WeChatBridge/` 存储目录，**不是与原版完全隔离的第二套应用**。
替换原版前先备份重要记录及设置，不要同时安装运行两份。此模式不读取另一套 `app-group` 存储；若原版使用该模式，测试包不会自动迁移那里的数据。
ad-hoc 签名随构建改变，更新测试包后可能需要重新授予辅助功能权限。

分享扩展能否出现在微信中、能否完成转发，必须在实际 Mac 上验证；CI 打包成功不代表这两项已经验收。
本流程不启用 Sparkle 自动更新，也不要求提供 Apple 账号、证书或公证密钥。

## 导入统一场景包

1. 下载同一版本附件 `WeChatBridge-<版本标签>-scenes.zip` 并解压；也可分别下载需要的场景 JSON，不要另存为网页。
2. 打开微信流的“设置 → 场景 → 场景管理”，通过“导入 JSON”多选解压出的四个 JSON，或将 JSON 拖入场景列表；不要直接导入 ZIP。
3. 确认出现“客户复盘（精简版）”“项目周会（精简版）”“日常摘要（精简版）”和“群聊精读”1.1.0。三个精简版使用独立 ID，不覆盖内置模板；“群聊精读”沿用原 ID 更新，同版本覆盖前先导出需要保留的本地修改。更新 App 不会自动更新已经导入的场景或切换群绑定。
4. 从微信选择少量聊天记录转发，在场景选择中选“群聊精读”，不要选“直接转发”。默认输出短语要点和勾选待办；追问“展开某条”再看详细证据。检查目标 AI 收到文件及完整场景要求，再核对决定和待办是否准确。

## 场景与 Codex 对话选择

- 默认每次转发选择场景，只预选上次使用的场景。快捷键已明确选定下次场景、或收集面板已经选好场景时，不重复询问。
- “此群以后使用这个场景，不再询问”默认不勾选。只有明确勾选才自动沿用；可在“设置 → 场景 → 群聊匹配”中点击“恢复每次选择”。旧群绑定保留作预选，不自动视为同意跳过。
- 未识别群名时仍可选择场景，但不能记住为某个群的自动场景。
- 发送到 Codex 时，先选“新建对话”或“选择已有对话”。新建使用[官方的 `codex://threads/new` 入口](https://learn.chatgpt.com/docs/reference/commands#deep-links)；已有对话在 Codex 中自行选择，不读取 Codex 的私有会话数据库。
- 两种方式都需要确认目标对话，再点“粘贴到这个对话”。新建后如需选项目，请先选好；旧 Codex 版本若没响应新建入口，请手动新建再确认。应用只粘贴，不替你发送。
- 新建对话不会附加上次总结的时间限制，会分析本次选择的全部消息；已有对话保持原来的续聊规则。
- 取消或超时不会粘贴，也不记为已送达。安装包需在实际 Mac 上验证新建、已有对话、取消和超时；这里只说明实现约定，不代替真机验收。
- Dock 图标已有开关：点击顶部菜单栏微信流图标，在“通用”中开启“在 Dock 中显示”。

## 长提示词编辑与卡顿复测

提示词编辑区和转发预览分别使用固定高度、内部滚动，长文本不再依靠自动增高的多行输入框计算整页高度。现场连续取样曾在 `VerticalTextField.updateVerticalSize`、`NSTextFieldCell.cellSizeForBounds` 和 CoreText 中文排版中发现主要耗时；本次替换的是该编辑控件，不改变场景保存格式、群绑定或权限。

更新后请用原先会卡顿的场景依次检查：从 Dock 恢复窗口、连续切换场景、滚动提示词、编辑后重开及插入技能，再导入场景 JSON。CI 的原生视图测试会检查长中文提示词确实使用有界的滚动编辑区；它不等于已经验证用户 Mac 的流畅度。若仍有彩球，需重新取样检查剩余原因，不将所有卡顿都归因于同一个控件。

场景是提示文本，不是代码插件，不安装额外技能。当前支持场景导入的原安装版本也能直接试用，无需先安装本 Fork。
本包不覆盖内置场景，不自动绑定所有群，也不凭关键词抢占现有场景。
提示词只能降低模型误判或执行聊天中恶意指令的风险，不能保证模型一定服从。不要拿高敏感聊天做首次测试。
转发给目标 AI 后，是否上传云端由该 AI 应用决定，不是本程序“本地处理”就代表目标 AI 也离线。

## 如何触发自动打包

流程文件为 `.github/workflows/macos-test-release.yml`。**必须先将本流程及配套文件合入目标提交，再推送指向该提交的版本标签。**

接受 `vX.Y.Z` 或 `vX.Y.Z-test.N`，例如 `v0.1.15-test.1`。两种标签都会发布成测试版，不标为 Latest。
标签的主版本号写入应用版本，GitHub 运行编号写入内部构建号。

确认要发布后，在本 Fork 的本地仓库执行以下操作；将占位内容替换为实际提交 SHA：

```sh
git tag v0.1.15-test.1 <包含本流程的提交SHA>
git push origin refs/tags/v0.1.15-test.1
```

随后在仓库 Actions 查看 `macOS Test Release`：

1. macOS runner 运行 Swift 测试（含场景解码/渲染测试）、翻译和发布配置检查。
2. 复用 `make-app.sh` 的开发签名模式构建双架构 App，检查签名，再用不依赖 Finder 的方式生成、验证 DMG。
3. 构建任务只有仓库读取权限；独立发布任务取得本次产物，校验 SHA-256 后上传至**当前 Fork** 的测试版 Release。
4. Release 附带 DMG、场景包、本文、源码检查报告、构建信息和校验文件；CI 中间产物保留 7 天，Release 附件不受这 7 天影响。

不需要额外配置签名 Secrets。仓库必须允许 Actions 运行及发布任务申请 `contents: write`；组织策略禁止时需要仓库管理员处理。
不要先在 Releases 页面手工创建同名版本，否则自动发布会因版本已存在而失败。
测试或打包失败不会进入发布任务；已有同名 Release 不会被覆盖。若上传失败留下草稿，先检查草稿和日志，不要反复改动旧标签或强推；处理草稿后再重试，或用新标签重建。

## 首次安装后验收

- 打开 App，确认无异常请求、无无法解释的持续磁盘增长。
- 按需授予辅助功能权限，检查微信中的分享入口；不需要识别群标题时不必额外开启屏幕录制。
- 导入“群聊精读”，转发不含敏感信息的测试记录，确认场景被附加且没有自动替你发送消息。
- 查看历史记录及保留期限，清理不需要的收集任务。过期记录通常移入废纸篓，释放空间还需清空废纸篓。
- 如扩展不能加载或权限异常，保留错误信息；不要把 Gatekeeper 校验、扩展加载和目标 AI 的权限问题混为一谈。
