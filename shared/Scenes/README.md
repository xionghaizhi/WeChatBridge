# 自定义场景

## 统一待办格式包

以下四个场景均为 1.1.0，默认短语要点和 Markdown 勾选待办，不输出待办表格：

- `customer-review.wechatflow-scene.json`：客户复盘（精简版），聚焦需求、承诺、风险和下一步。
- `project-sync.wechatflow-scene.json`：项目周会（精简版），聚焦进展、决定、阻塞和待办。
- `daily-summary.wechatflow-scene.json`：日常摘要（精简版），合并关键变化，不逐条复述。
- `group-close-reading.wechatflow-scene.json`：群聊精读，保留原有场景 ID，可更新已经导入的旧版。

每项待办包含标题、内容、负责人和截止时间。没有明确负责人或期限时标为“待确认”，不猜测；已经完成的事项不列为未完成待办，不因摘要精简而遗漏实际待办。追问“展开某条”时才补详细说明和依据。

解压统一包后，在“设置 → 场景 → 场景管理 → 导入 JSON”中多选四个 JSON 文件；不要直接导入 ZIP。已存在同版本“群聊精读”时，仅在确认愿意替换本地修改后点“覆盖”；有本地修改时先导出备份。

三个精简版使用独立的自定义场景 ID，不冒充官方模板。原版 App 重启时会恢复其内置官方模板，所以不能靠同 ID JSON 永久覆盖它们。导入后可停用不再需要的原版场景，但群绑定不会擅自切换：若此群已记住原版，请在“群聊匹配”恢复每次选择，再选精简版并按需重新记住。

仅更新场景 JSON 不需要重新安装 App 或重新授予辅助功能权限，现有支持场景导入的版本即可使用；编辑器卡顿修复则需要安装新版 App。公众号文章提取、视频信息读取没有待办模板，保持不变。自定义或复制过的其他本地场景不会被扫描、覆盖。

这些场景只分析资料，不会创建日历事件或提醒事项，也不因聊天中的指令执行外部操作。若要由本机 Codex 写入提醒事项，需另行明确指示、确认条目和日期，并授予对应系统权限；本包没有包含或安装写入工具。

## 群聊精读

`group-close-reading.wechatflow-scene.json` 是可直接导入的“群聊精读”，不是一句“请总结”。
1.1.0 默认只给最多三条短语要点和勾选待办，不再铺长文或表格。
待办包含标题、内容、负责人和截止时间；没说清的标为待确认，不编造。
想深入时直接追问“展开排查机房异常”或“给我第2条的依据”，再针对该项补充详细说明和来源。

在微信流“设置 → 场景 → 场景管理”中导入 JSON 并启用；转发时选“群聊精读”，不要选“直接转发”。
新测试版默认每次选择，预选上次场景；只有勾选“此群以后使用这个场景，不再询问”才跳过。
可在“设置 → 场景 → 群聊匹配”中点击“恢复每次选择”。旧版 App 仍按其原来的群绑定规则执行。
也可以直接把 JSON 拖入场景列表。导入不覆盖原有内置场景，不需要重新安装 App 或额外技能。
已导入 1.0.0 的用户需要重新导入 1.1.0 才会更新提示词；仅升级 App 不会覆盖本地场景。

`keywords` 刻意留空，避免导入后凭关键词改变已有群聊匹配。请自行选择使用范围。
没有实际记录时不会编造负责人、日期和决定；这些是对模型的要求，不代表模型输出免检。

完整步骤见[测试版说明](../../docs/macos-test-release.zh-CN.md)，安全边界见[源码检查报告](../../docs/macos-source-review.zh-CN.md)。
